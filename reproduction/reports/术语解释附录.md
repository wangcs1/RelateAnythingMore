# 附录：缩写、术语、符号与表格字段解释

这份附录面向第一次阅读场景图论文的读者。解释均以本报告实际使用的设置为准，同一缩写在其他论文中可能有不同定义。正文保留原有实验记录；读不懂某个词时，可以用编辑器的搜索功能在本附录查找英文或中文。

## A. 先用一个例子理解整个任务

图片中有一个人和一辆自行车。我们给它们固定编号：人是 **#6**，自行车是 **#24**。希望模型输出“#6 → riding（骑着）→ #24”。这叫一个**关系三元组**，三个位置依次是主体、关系、客体。

本次实验已经把物体框交给模型；模型不用自己寻找物体，也没有被告知哪个框是人、哪个框是自行车。它先挑选值得判断的有向物体对，再给词表里的每种关系打分。正式评测时，每对只留一个最高分关系，整张图片按分数排序，取前50条，与人工标注逐项比较。

因此，“riding在#6→#24这对中的56个词里第一名”与“这条关系在整张图的所有候选中第二名”是两种排名。T01里两者分别为1和2。它进入前50条并精确匹配GT，因此命中；但整张图的5条GT只命中2条，所以这张图的R@50为2/5=40%。

## B. 实验编号与阅读路线

这些编号是本地实验标签，不是论文通用缩写。

| 编号 | 中文含义 | 它回答什么问题 |
|---|---|---|
| B01 / baseline | 基准实验、作为比较起点的原始设置 | 官方权重在完整测试集上能否得到接近论文的数字？ |
| V01 | 可视化实验 | 指定区域的注意力主要读取图像的哪些小块？ |
| T01 / trace | 单样本追踪 | 同一条真实关系从数据记录到最终判分如何流动？ |
| E01 | 关系表达与词表实验 | 把riding改成riding on等表达，判断是否稳定？ |
| E02 | 框扰动实验 | 框的位置或大小出现误差时，结果如何变化？ |
| E03 | 关系存在性分数实验 | 去掉pair logit后，排序和召回如何变化？ |
| E04 | 图像证据干预实验 | 灰度、模糊、均值图、错配图像对预测有何影响？ |
| D01 | 最终标注审计 | 标注中有多少重复记录、多谓词关系，人工查看暴露什么问题？ |
| R01 | 按审查意见进行的证据闭环和补充实验 | 加载、样本、原始输出、重复运行和报告解释是否互相对应？ |
| E01b | 原E01的事后语义分层 | 区分等义/近义/不等义/不确定；本轮仅助手重标，不是独立盲审的新基准。 |

建议顺序：先读本附录A、C、D，再看正文B01的结果表；接着结合T01图片读E、F、G；最后读控制实验及本附录H、I。第一次阅读可以暂时跳过512维向量的具体数字和精度差表。

## C. 任务、数据集与标注

| 缩写或术语 | 全称或中文 | 在这份报告中怎样理解 |
|---|---|---|
| RelateAnything | 项目/模型名称 | 根据图像和物体区域，为候选关系文本打分的模型。名称不是某个评测指标。 |
| SGG | Scene Graph Generation，场景图生成 | 用“物体是节点、关系是有向边”的图描述图像，如“人→骑着→自行车”。 |
| 场景图 | Scene graph | 一张关系网络图；与模型内部的“场景特征图”不是同一个东西。 |
| SGCls | Scene Graph Classification，场景图分类 | 提供真实物体框，在框之间判断关系。本报告采用官方SGClsEvaluator的具体契约，模型不输入物体类别；不要只根据任务简称猜测输入。 |
| SGDet | Scene Graph Detection，场景图检测 | 还需要先检测物体位置和类别，再预测关系；检测漏框会限制后续关系召回。本轮没有运行真实检测器。 |
| PSG | Panoptic Scene Graph，通常译为全景场景图 | 数据集名称；原始任务包含全景分割，本轮读取公开COCO格式并用其物体框做关系评测，不是复现分割任务。 |
| COCO / PSG-coco-format | Common Objects in Context；此处也指一种常见标注组织格式 | JSON里按images、annotations、categories等列表存图像和对象。本轮的COCO格式不表示使用整个COCO训练集。 |
| RA-4M | 论文发布的关系标注训练数据名称 | “4M”是名称中约四百万规模的提示，不能当作精确图片数。本报告所用PSG测试集不是它。 |
| VLM | Vision-Language Model，视觉语言模型 | 能同时处理图像和文字的大模型，可用于生成关系标注；不是当前负责关系打分的轻量模型。 |
| Gemma / Gemma-26B / Gemma26B | Gemma模型家族；26B表示约260亿参数 | 官方数据生成链涉及的大模型。不能把其所有参数都需要存储与每次激活多少参数混为一谈。本轮未运行它。 |
| GT | Ground Truth，作为评测依据的参考真值/标注 | 例如人工标注的框和关系。GT也可能有漏标或歧义，但评测必须按规定参考它。 |
| GT框 | Ground-truth bounding box | 数据提供的真实物体框。给了框不等于给了“骑着”的关系答案。 |
| 检测框 | Detected box | 检测器预测的框，可能偏移、漏检或多检；与GT框设置难度不同。 |
| 标注 / annotation | 对图像内容的记录 | 物体类别、位置、关系等；不是模型的预测结果。 |
| subject / 主体 / 主语 | 关系的起点 | “人骑车”里是人。这里“主体”不是一定更重要的物体。 |
| object / 客体 / 宾语 | 关系的终点 | “人骑车”里是车。object也可泛指一个物体，需要结合上下文。 |
| predicate / 谓词 | 两个物体间的关系标签 | riding、on、beside等；机器视觉里不局限于语法上的动词。 |
| relation / relationship | 关系 | 泛指主体与客体之间的联系；一条完整记录通常包含两个物体索引和一个谓词。 |
| 三元组 | Triplet | 本地存储顺序是(subject, object, predicate)，如(6,24,46)；文字展示常写“主体→谓词→客体”，两者排列顺序不同。 |
| 有向物体对 / directed pair | 顺序有意义的两个物体 | (#6,#24)与(#24,#6)不同；反过来可能需要“被骑着”而非“骑着”。 |
| 类别 / category | 物体类别 | person、bicycle、road；与riding这样的关系类别不同。 |
| 开放词表 | Open vocabulary | 可以安装新的文本候选进行打分；不自动意味着任何未见概念都识别正确。 |
| 词表 / vocabulary | 候选关系短语列表 | 正式PSG评测为56词；每个词对应一个文本向量。不是让模型自由生成一句话。 |
| 模板 / template | 编码短语所用的固定文字格式 | 用统一句式包装关系短语再编码，减少格式差异。使用官方TRAIN_TEMPLATES。 |
| prompt | 提示词 | 给VLM的文字任务说明，或模型中用于编码位置的提示；box prompt不是自然语言提问。 |
| 语义轮 / grow轮 / 空间轮 | 数据生成的不同阶段 | 分别生成语义关系、补充关系、空间关系；grow意为补充/扩展，不是训练轮数。 |
| 清洗 / 过滤 / 几何验证 | 清理候选标注 | 删除格式错误、重复或几何不合理关系等。没有过滤前记录就不能证明过滤器带来多少提升。 |
| ontology | 本体、关系知识组织 | 用于描述关系间的同义、对称等结构的资源，不是另一份图片数据。 |
| train / val / test | 训练集 / 验证集 / 测试集 | 分别用于学参数、选设置、最终检验；本轮不拿test训练。 |
| 数据划分 / split | 数据集中的某个部分 | 如test；同一图片不能在需要严格独立的训练与测试中泄漏。 |
| 零样本 / zero-shot | 不针对当前评测目标再训练 | 本报告主要指发布权重直接评测；不据此保证发布模型从未见过任何相似图片或语义。 |
| 未见语义泛化 | 识别训练中未覆盖的关系含义 | 比“换个字符串还能打分”更强，需要严格核对训练语义与测试划分。 |
| 跨数据集迁移 | 在另一个数据集上使用模型 | 还要核对框、类别、词表和评分设置；单测PSG不证明所有数据集迁移。 |

## D. 指标、排名与“命中”的准确含义

| 缩写或术语 | 中文解释 | 本报告中的计算或例子 |
|---|---|---|
| R / Recall / 召回率 | 参考答案中有多少被找出来 | 5条GT命中2条，召回率40%。不是“所有输出里40%正确”。 |
| R@K | 每图前K条预测的召回率，再对有效图片平均 | K可为20、50、100；正式R@50约40.11%。每图GT按协议去重。 |
| R20 / R50 / R100 | R@20 / R@50 / R@100的简写 | 不是模型名字，也不是实验图片数。 |
| mR / mean Recall | 按谓词类别平衡的平均召回率 | 先对每类在含该类GT的图片上计算并平均，再对类平均，避免高频关系完全主导。 |
| mR@K / mR50 | 取前K条时的类别平均召回 | 此实现每图每类分母保留重复标注，和R的去重处理不同；应按本项目评分器理解。 |
| F1 / F1@K | 此报告中R和mR的调和平均 | F1=2×R×mR/(R+mR)。这里不是常见的precision与recall的F1，不能套用另一种定义。 |
| Precision / 精确率 | 输出中有多少是正确的 | 分母是预测数量，和召回率不同；未完整标注时不能把未匹配输出都当确定错误。 |
| TP | True Positive，真阳性/正确命中 | 与GT匹配的预测。pooled TP/GT意为先加总命中数再除以GT总数。 |
| pooled R / pooled recall | 把多图关系放在一起算的召回 | 大量关系的图片权重更大，不等于每图平均R，也不等于每类平均mR。 |
| macro / 宏平均 | 先算每个单元，再平均 | 单元可以是图或类别，需要说清；本报告主指标有明确逐图、逐类顺序。 |
| top-k / topk / top50 / top100 | 按分数取前k项 | 在采样处取物体对，在评测处取最终关系，不能把不同阶段的k当作同一个。 |
| rank / 排名 | 排序后的名次，通常从1开始 | image_rank=154表示整张图排154，不是槽位编号。 |
| 对内排名 / within_pair_rank | 固定一对，比较所有候选谓词的名次 | 在56词里riding排第1；不代表在整张图关系中第1。 |
| 全图排名 / image_rank | 每对留下最佳词后，跨物体对排序 | riding主线在T01排第2；前50会包含它。 |
| argmax | 取最大值的位置/编号 | 在56个词的分数中取最高分词的编号；max取的是最大数值。 |
| graph_constraint=True | 图约束：一对只保留一个最佳谓词 | 同一对即使有两个GT谓词，正式解码也只留一个，因此可能限制多标签召回。 |
| 精确匹配 / 严格匹配 | 主体、客体、谓词编号均一致才算 | “driving on”与“on”可能都看似合理，但本评测不按同义词自动合并。 |
| hit / hit20 / hit50 / hit100 | 是否在对应前K预测中命中GT | True为命中，False为未命中。 |
| hit50（失败分类中的名称） | 在前50正确命中 | 是成功类别，和三个失败类别并列统计。 |
| not_selected | GT物体对没有进入采样候选 | 模型后面的谓词打分阶段没有机会判断这对。 |
| wrong_predicate | 物体对已选，但最佳谓词与GT不同 | 例如GT是driving on，模型留下on；增加评测K不能自动换回GT词。 |
| rank_below50 | 对已选且最佳词正确，但全图排在50之后 | T01的looking at排154，属于此类。 |
| pair coverage / 候选对覆盖率 | GT关系中有多少的物体对被采样保留 | 只检查(s,o)能否进模型，不要求谓词预测正确。 |
| selected predicate accuracy | 已选中GT关系的最佳谓词正确率 | 分母只含被采样覆盖的GT关系；不是全图R@50。 |
| 召回上限 | 后续完美也无法超过的理论限制 | 某GT对没被采样，后续再准也不能召回它；多GT谓词还受图约束限制。 |
| 阈值 / threshold | 决定是否输出的分数门槛 | 如score≥0.3；本轮主表主要按排名取K，不是在测试集调最优阈值。 |
| 校准 / calibration | 让分数能更可靠地表示置信程度 | sigmoid输出0.99不代表经验证有99%正确概率；这需要额外验证。 |
| 百分点 | 两个百分数直接相减的单位 | 40%到41%是+1个百分点，相对增长为2.5%；正文的差值列用百分点。 |
| 独立复算 | 用另一份独立逻辑重算同一批输出 | 用于发现评分实现错误；不表示另训了模型或另请了人工标注者。 |
| 去重 / duplicate | 合并重复三元组 / 重复记录 | 同一(s,o,p)记录出现两次属于重复；同一(s,o)配两个不同p属于多标签，不是重复。 |
| multilabel / 多标签 | 同一对有多个关系标签 | 如既有on又有riding；这与每对只能输出一个词的设置可能冲突。 |

## E. 张量、坐标、索引和数据字段

| 术语或字段 | 通俗解释 | 读表时注意 |
|---|---|---|
| tensor / 张量 | 多维数字数组 | 图片、框、特征、分数都可用张量装；不是特指某种模型层。 |
| shape | 各维长度 | [1,400,56]表示1张图、400个物体对、每对56个谓词分数。 |
| 维度 / dim / channel | 向量中数字的位置或数量 | 一个512维向量有512个数；不能将每维直接命名为某种人类语义。 |
| B / N / K / V / D | 张量维度符号 | 本文通常为批内图片数、每图框数、候选对数、词表大小、特征维数。 |
| K的两种用法 | 采样候选数或评测保留数 | logits里的K=400，而R@50的K=50；attention中的K还可能表示Key，按上下文区分。 |
| W / W[p] | 文本向量矩阵 / 第p个谓词的文本向量 | T01为[56,512]；W[46]对应riding。W不是物体框宽度。 |
| s / o / p / j | 主体索引、客体索引、谓词索引、循环位置 | 示例s=6,o=24,p=46；正文小写w、h还可表示框宽高。 |
| ID / id | Identifier，身份编号 | 编号可以不连续，也不必等于数组位置。 |
| index / local_id / 局部索引 | 某个列表内部的位置 | 通常从0开始；#6表示当前图第7个框，不是全数据集第6号人物。 |
| global_id / 全局ID | 跨当前数据文件识别实体的编号 | T01主体原始annotation.id=343，映射为本图局部框6。 |
| image_id / file_name | 图像ID / 图像文件名 | image_id=1159713与Dataset index=20不是同一种编号。 |
| annotation.id / relation.id | 对象标注ID / 关系记录ID | 一条关系的subject_id和object_id要先解析，不能未经映射直接当框位置。 |
| subject_id / object_id / predicate_id | 原始主体/客体/关系ID | 原始ID要经过映射，才成为模型用的局部索引和词表列号。 |
| images | 图像张量 | 通常[B,3,H,W]，3是RGB颜色通道；图像像素先缩放到[0,1]。 |
| RGB | Red、Green、Blue，红绿蓝 | 普通彩色图像的三个颜色通道。 |
| boxes | 框的坐标数组 | 本模型用归一化cxcywh；不是每张裁剪后的图片。 |
| counts / box_counts | 每张图的有效框数 | 批处理会补齐到最大框数，用它区分真实框和补位框。 |
| padding / 补齐 | 为凑齐张量尺寸而加的占位项 | 不能把补位框或无效槽位当成真实物体。 |
| mask / valid_mask | 掩码 / 标记哪些项有效 | 布尔掩码是True/False数组；它与分割物体轮廓的mask用途不同。 |
| 分割mask / raster | 区域轮廓掩码 / 栅格化区域 | 逐像素或逐格指示区域覆盖；本轮主要使用框区域。 |
| xywh | 左上角x、左上角y、宽w、高h | 原始标注常用像素单位。 |
| xyxy | 左上角x1,y1与右下角x2,y2 | 便于画框、算交集。 |
| cxcywh | 中心cx、中心cy、宽w、高h | 本模型输入的框表示。归一化后横向除图宽、纵向除图高。 |
| 归一化坐标 | 用图像宽高作单位 | cx=0.5表示在图像横向中央，不是0.5像素。 |
| resize / 方形缩放 | 直接将原图缩为448×448 | 宽高比可能改变，但归一化框坐标不变。 |
| letterbox | 保持比例缩放后填边 | 与本轮直接拉成方形不同；不能按填边坐标解释本轮框。 |
| pack | 把原始标注整理为连续数组 | 不是压缩图片；将ID映射、坐标转换等提前完成以便快速读取。 |
| memmap / 内存映射 | 把磁盘数组按需映射读取 | 不必一次将所有标注数组复制到内存。 |
| Dataset | 数据读取对象 | 按index返回图片、框、targets；是代码类名，不只是“数据集”的英文。 |
| collate / collate_fn | 将多份样本拼成一批 | 负责补齐框、汇总counts和targets等。 |
| img_meta | 每张图的索引元信息 | 此处依次为图像ID、宽、高、框起点、框数、关系起点、关系数。 |
| width / height / box_count / relation_count | 图宽 / 图高 / 框数 / 关系数 | T01为640、428、35、5。 |
| offset / box_offset / relation_offset | 数组起始位置 / 框起点 / 关系起点 | 是数组中的绝对行号，不是框的空间偏移量。 |
| rels / relations | 存储的关系数组 | pack的rels有额外列，targets['relations']只保留(s,o,p)三列。 |
| targets / target | 监督或评分用的参考答案 | targets=None表示这次模型前向没有接收关系GT；前向后评分器仍需读取GT。 |
| rel_categories | 原始关系类别列表 | 文件顺序决定映射后的词表编号。 |
| rel_flags | 每条关系的标记位 | 可标示空间、几何生成及来源轮次等；未置位不自动等于某种人工语义分类。 |
| rel_weights | 每条关系的监督权重 | 训练时可改变不同关系的损失影响；不是最终预测分数。 |
| entity_labels | 对象类别的数字编码 | 本轮保留在targets做解释，但没有传给模型作为物体类别输入。 |
| src | source，数据来源编号 | 混合数据训练时用于区分来源；不表示图片左上角位置。 |
| slot / 槽位 | 采样后某一对占据的位置 | slot=6是输出数组中的第7行，和subject索引6恰好相同但含义不同。 |
| multi_hot / 多热标签 | 一个槽位可有多个True的标签向量 | [0,6,46]=True表示第0张图的槽6有riding标签；不是模型预测概率。 |
| build_slot_targets | 官方标签映射函数 | 把GT三元组放到已采样槽位对应列；T01在预测之外独立调用，用于核查标注与候选索引的一致性。 |

## F. 模型部件、特征与注意力

| 术语 | 中文解释 | 本项目中的作用 |
|---|---|---|
| backbone / 骨干 | 负责从图片提取通用特征的主网络 | 先看整张图，输出供后续关系判断使用的场景特征。 |
| ViT / ViT-S+ | Vision Transformer；小型增强规格的视觉Transformer名称 | 将图像按patch处理的骨干；S+为型号标签，不是性能分数。 |
| DINOv3 | 视觉自监督模型家族名称 | 与骨干初始化有关；本轮使用已发布完整权重，没有重新做自监督训练。 |
| feature / 特征 | 网络计算得到的数字表示 | 与原始RGB不同；可能编码外观、形状和上下文，但每维通常不能直接解释。 |
| F_map / scene feature map / 场景特征图 | 按空间网格排列的特征 | T01形状[1,28,28,384]：每个网格位置一个384维向量。它不是“场景图”关系网络。 |
| patch | 图像小块 | 448输入对应28×28网格，即784个位置；特征看小块也可受全图上下文影响。 |
| token | 网络处理的一个向量单元 | 可来自图像patch、框角点或其他表示，不一定是一个汉字或英文单词。 |
| embedding / 文本向量 | 将文字变成固定长度数字 | 不同短语得到不同向量；相似向量不保证在具体图片里语义等价。 |
| 文本编码器 / text student | 负责把短语变为向量的模型 | 本地从text_student.pt加载，用于构建W；不是图片关系打分网络本身。 |
| projection / proj / 投影 | 把一个特征变换到另一维度或空间 | 常由线性层或小网络完成，不是把三维物体投影到二维图片。 |
| MLP | Multi-Layer Perceptron，多层感知机 | 简单的多层全连接网络；geo_scorer用它根据几何特征预筛选物体对。 |
| LayerNorm / compose_norm | 层归一化 / 查询合成后的归一化模块 | 调整数值分布；不同于为求余弦相似度而把向量长度变成1。 |
| concat | concatenate，按维度拼接 | 四个384维视觉向量加512维几何编码，共2048维pair_input；不是把数字逐项相加。 |
| sampler / 采样器 | 筛选与排列有向物体对的模块 | 此处按学习到的分数top-k，不是随机抽签。 |
| geo / geometry | 几何 | 框的位移、长宽比例、重叠等空间量，不直接包含颜色纹理。 |
| geo_scorer | 几何评分网络 | 对所有有效有向对评分，保留geo_budget个；GT不会在推理时强制保留。 |
| geo_budget / final_budget | 几何阶段 / 最终阶段候选对预算 | 本轮均为400，所以第二阶段对保留对重排，未进一步减少有效对。 |
| f_sub / f_obj | 主体 / 客体相关性特征变换 | 对同一物体以不同角色生成表示，再内积估计这一对是否值得判断。 |
| pair relatedness / 物体对相关性 | 两个框是否可能形成值得描述的关系 | 不区分具体是riding还是holding；产生pair logit。 |
| SoftSpatialPool | 带空间偏置的柔性区域特征汇聚模块 | 用区域query读全图patch，汇聚一个区域向量；不是只截框内像素再单独编码。 |
| pooling / pool / 汇聚 | 把多个位置的特征合成一个向量 | soft表示用连续权重，可读取框外上下文。 |
| subject / object区域 | 主体框 / 客体框区域 | T01为骑手框与自行车框。 |
| union / 联合区域 | 两个框的最小外包矩形 | 包括两框和中间范围；不是只取二者像素轮廓的并集形状。 |
| contact / 接触区域 | 两框交叠区或面对边之间的间隙 | 几何构造，不保证真有物理接触，也不是人体关节点。 |
| region / 区域 | 图像中的一个指定范围 | 可是框、union、contact或mask，需看具体输入。 |
| query / Q / q | 查询向量 | 像“读取信息的请求”；区域query读patch，与最终q_sem不是同一个层次的query。 |
| key / K | 键向量 | 用来与query比较，决定各位置被读取的权重；不要与top-K混淆。 |
| value / V | 值向量 | 根据注意力权重被加权汇总的内容；不要与词表大小V混淆。 |
| Attention / 注意力 | 按query与key相似度对value加权 | 简化公式softmax(QKᵀ/√d)V；表示信息读取分配，不是人类心理注意力的证明。 |
| softmax | 将一组数变为总和为1的权重 | 某项权重会受同组其他项影响；与对每个分数独立处理的sigmoid不同。 |
| MHA | Multi-Head Attention，多头注意力 | 并行使用多组query/key/value计算，再组合结果。 |
| head | 头 | “attention head”是注意力分组；“prediction head/文本头”是输出打分模块；不是同一个含义。 |
| cross-attention / 交叉注意力 | 一组query读取另一组信息 | 例如区域query读取全图patch。 |
| self-attention / 自注意力 | 一组元素在自身之间交换信息 | 例如关系对之间建模上下文。 |
| SDPA | Scaled Dot Product Attention，缩放点积注意力 | PyTorch可使用高效实现；快速路径通常不返回可画图的全部注意力权重。 |
| attention map / heatmap | 注意力图 / 热力图 | 用颜色画权重或特征数值；颜色亮不自动表示该区域是预测的必要原因。 |
| 注意力质量 / attention mass | 一个区域里权重的总和 | 这里“质量”意为mass、数量，不是“模型质量好坏”；0.8表示80%的权重落在区域中。 |
| patch面积占比 | 框覆盖的patch在全图patch中的比例 | 用来对照权重是否比纯面积分配更集中。 |
| 归一化熵 / entropy | 权重分散程度的量 | 低表示集中，较高表示分散；不能单凭低熵判断预测正确。 |
| 色标归一化 | 按指定范围映射颜色 | 每图/每query分别归一化时，两张图的同样红色未必对应同一绝对权重。 |
| Transformer / relation transformer | 用注意力组织信息的网络 / 关系上下文网络 | 让初始关系特征读取场景与框角点信息。 |
| box prompt / box_tokens | 框位置提示 / 框角点向量 | 每对有主体左上/右下、客体左上/右下四个token；不是新增四个物体。 |
| deformable_read / 可变形读取 | 围绕参考区域选择位置读取特征 | 用subject/object/union/contact作为anchors，提高读取的针对性。 |
| anchors | 参考区域 | 本文指四区域，不要套用检测器中固定候选框的另一种anchor含义。 |
| rel_interaction / 关系交互 | 关系表示结合其他关系与场景信息 | 后续输出interaction_context；不是再次人工输入GT。 |
| context / 上下文 | 当前物体对以外的有关信息 | 如道路、周围骑手和其他关系，有时有帮助，也可能造成混淆。 |
| q_sem / semantic query | 语义查询 | 汇合关系上下文与主/客体文本空间投影，用来匹配关系文本。 |
| q_spa / spatial query | 空间查询 | 由关系上下文与几何编码共同得到；不意味着这条分支完全不含视觉信息。 |
| sub_text_proj / obj_text_proj | 主体 / 客体视觉到文本空间的映射 | 处理的是视觉向量，不是直接输入person/bicycle文字类别。 |
| spa_proj / geo_encoded | 空间分支映射 / 已编码几何向量 | 前者生成q_spa，后者是19个原始几何量经网络变换后的表示。 |
| gate / g_s / g_o | 门控 / 主体和客体分量系数 | 控制它们在语义查询合成中的份量；和每个谓词的alpha不是同一个参数。 |
| pair_input / pair_proj / pair_projected | 拼接输入 / 关系投影模块 / 投影结果 | 三个名字分别是模块前、模块本身、模块后。 |
| relation_context / deformable_context / interaction_context | 三个上下文阶段的实际输出 | 是诊断保存的张量名称，不是额外训练了三个模型。 |
| pool_output_0 / pool_output_1 | 第一次 / 第二次区域汇聚输出 | 第一次对应所有物体框，第二次对应所有候选对的union及contact。 |
| reparameterize / 重参数化 | 将当前词表所需的打分参数预先整理 | 便于部署/评测，不是针对测试集再训练。 |

## G. 分数公式、数学符号与19维几何

先读这个小例子：T01中riding的实际谓词logit为5.44394，pair logit为0.21610。相加得到5.66004，再经sigmoid变成约0.99653。这个数很高，但它是排序分数，不应直接读成“99.653%概率一定骑着”。

| 名称或符号 | 解释 |
|---|---|
| logit / logits | 未经sigmoid变换的原始实数分数 / 多个此类分数。可以为负，也没有0到1限制。 |
| predicate logit | 对某一对、某一个谓词的原始分数。riding与eating各有一个。 |
| pair logit / pair_logits | 某一物体对整体的相关性分数。给这对的所有谓词加同一个数，不改变对内最高词。 |
| fused / fused logit | 融合后分数。本轮为predicate logit + pair_weight × pair logit。 |
| score / fused score | 融合logit经过评分契约变换后的值，本轮为sigmoid(fused logit)。 |
| pair_weight / pair-weight / w | pair logit的权重。E03比较1与0；不等于W文本矩阵或框宽w。 |
| sigmoid | 函数1/(1+exp(-x))，把任意实数压到0和1之间；严格递增，未饱和的精确算术中不改变排序。 |
| a=1,b=0 | 评分契约中的额外仿射校准系数：本轮没有额外缩放/平移。小写b不等于批大小B，也不等于文本头内部logit_bias。 |
| cos / cosine similarity / 余弦相似度 | 两向量方向的相似程度，通常在-1到1；先单位化再点积。不是预测概率。 |
| cos_sem / cos_spa | 语义 / 空间查询分别与同一文本向量的余弦相似度。 |
| alpha / alpha_p | 针对第p个文本谓词的分支混合系数；0更偏语义，1更偏空间。它不是当前图片的注意力权重。 |
| mixed cos / cos_p | (1-alpha_p)×cos_sem + alpha_p×cos_spa。 |
| scale / logit_scale | 本文可指文本分数缩放，实际为exp(logit_scale)并设上限；E02里的scale则指改变框大小。 |
| bias / logit_bias | 给混合余弦缩放后加上的偏置，用于形成谓词logit；T01约-4.69709。 |
| dot product / 内积 | 对应维相乘后求和；未先归一化时也受向量长度影响。 |
| L2范数 / norm | 向量长度sqrt(sum(x_i²))。范数大不自动意味着关系更正确。 |
| L1差 | 各维绝对差之和；表中“平均head L1差”还先在各head等维度上平均。 |
| max abs / max_abs / 最大绝对差 | 对应元素之差取绝对值，再取最大的一个；0表示该比较中逐元素相同。 |
| relative max / 相对最大差 | 用参考数值尺度归一化后的差，具体分母遵循诊断脚本。不同指标不能直接混比。 |
| FP32 reconstruction / FP32重构 | 将实际捕获向量转为32位浮点，再按公式讲解性复算；不保证等于原混合精度矩阵运算逐位结果。 |
| clamp | 将数值限制在指定上下界，超界部分截到边界。 |
| tanh / 软限幅 | 双曲正切；10×tanh(x/10)平滑压缩较大幅值，不是硬截断到[-10,10]。 |
| exp / log / sqrt / sum | 指数e的幂 / 自然对数 / 平方根 / 求和。 |
| 均值 / mean / min / max | 平均值 / 最小值 / 最大值；mean也可能出现在mean_image条件名中。 |
| 1e-5 / 2e-05 | 科学计数法：分别为0.00001、0.00002；负号在指数中不表示数值本身为负。 |

19维几何特征的下标从0开始。以下说明的是软限幅前的定义，报告表里保存的是经过10×tanh(x/10)后的结果；公式中的宽高与面积有防止除零的小量处理。

| 编号 / 名称 | 中文解释 | 正负或大小怎样理解 |
|---|---|---|
| 0 / dx | 客体中心相对主体中心的水平位移，除以主体宽 | 正数通常表示客体在右边。 |
| 1 / dy | 客体中心相对主体中心的垂直位移，除以主体高 | 图片y向下增大，所以正数表示客体更靠下。 |
| 2 / log_wr | log(客体宽/主体宽) | 正数表示客体更宽。 |
| 3 / log_hr | log(客体高/主体高) | 正数表示客体更高。 |
| 4 / log_ar | log(客体框面积/主体框面积) | 正数表示客体框更大。 |
| 5 / log_as | 主体归一化框面积的对数 | 归一化面积小于1时通常为负数。 |
| 6 / log_ao | 客体归一化框面积的对数 | 与log_as类似。 |
| 7 / IoU | Intersection over Union，框交并比：交集面积/并集面积 | 0表示不交叠，1表示两框完全相同；框IoU不代表物体真实接触程度。 |
| 8 / s_in | 交集占主体框面积的比例 | 主体被交集覆盖的程度。 |
| 9 / o_in | 交集占客体框面积的比例 | 客体被交集覆盖的程度，可能与s_in差很多。 |
| 10 / asp_s | 主体框宽高比的对数 | 正数偏宽，负数偏高。 |
| 11 / asp_o | 客体框宽高比的对数 | 同上，用于客体。 |
| 12 / cos_theta | 两中心连线的水平方向分量 | 与dx有关，但用中心距离归一化。 |
| 13 / sin_theta | 两中心连线的垂直方向分量 | 图像y轴向下，因此其正数方向与通常数学坐标图不同。 |
| 14 / delta_cy | 客体中心y减主体中心y | 未除以主体高，和dy不同。 |
| 15 / fill_s | 主体真实区域面积占其框面积的比例 | 没有mask、只用框时，限幅前默认1。 |
| 16 / fill_o | 客体真实区域面积占其框面积的比例 | 同上。 |
| 17 / r_iou | 区域交并比 | 只用框时退化为框IoU。 |
| 18 / r_contact | 区域交集面积除以两个区域中较小者面积 | 描述小区域被交叠覆盖程度；并不直接证明物理接触。 |

## H. 对照实验、统计和结论边界

| 术语 | 解释及本报告例子 |
|---|---|
| 控制变量 | 比较两次结果时，固定图像、GT、权重等，只改变所研究因素。 |
| baseline / original / control | 原始基准 / 原始输入 / 对照条件，作为变化前的参照。 |
| intervention / 干预 | 主动改变输入或计算，如模糊图片；与仅观察注意力不同。 |
| 扰动 / perturbation | 给框加可控误差，不是换掉GT身份或重新标注GT。 |
| translation | 平移框中心：高斯噪声×level×各框宽高，框大小不变。 |
| scale（E02） | 改变框宽高：乘以exp(高斯噪声×level)，中心不变。 |
| level / intensity | 扰动强度参数。0.20不是“每个框固定移动图宽的20%”，也不是固定20% IoU损失。 |
| Gaussian / 高斯噪声 | 通常集中在0附近、少量较大的随机数；用于产生不同方向/幅度的框误差。 |
| lognormal / 对数正态缩放 | 对高斯噪声取指数得到正倍率；保证框宽高的倍率为正。 |
| seed / 随机种子 | 控制伪随机序列的起点，使同一代码和设置下的随机扰动可重跑。 |
| 三seed均值 | 用101、202、303三组随机扰动结果取平均，不等于三套独立数据集。 |
| SD / standard deviation / 标准差 | 多次结果的波动大小；不是均值，也不是置信区间或统计显著性的直接证明。 |
| bootstrap / 自助重采样 | 从已有样本有放回抽样多次，再重算统计量，估计这批样本支持的波动范围。不是重新训练模型或凭空增加真实图片。 |
| paired bootstrap / 配对自助重采样 | 同一张图的原始/干预输出一起被抽中，比较其差值，避免错开两个条件的图片。 |
| cluster bootstrap / 聚类自助重采样 | 按图片抽样，将同图的全部物体对/改写一起带入；防止把高度相关的多条结果当独立样本。 |
| CI / CI95 / 95%区间 | Confidence Interval，置信区间；此处为bootstrap分布的2.5%与97.5%分位点，受样本和方法假设限制。区间跨零表示数据尚不能排除零差异，不等于证明完全一样。 |
| 事后诊断 / post-hoc | 已看过旧结果之后重新分析；可帮助定位问题，但不应冒充事前设计、独立盲评。 |
| 盲审 / 独立语义核验 | 标注者不参考模型分数，根据图片与定义单独判断；本轮没有第二人独立盲审。 |
| E / N / X / U / F（E01b） | E等义，N近义但有额外含义，X不等义，U不确定；控制词F表示助手认为该有向对中为假。与通用False或F1不同。 |
| 多重比较校正 | 同时比较很多条件时控制偶然发现的统计方法；本报告bootstrap区间未作此校正。 |
| 配对比较 / paired | 同一图片在改变前后比较，尽量减少图片内容不同带来的混杂。 |
| 均匀抽样 | 按数据顺序等间隔取300图，不按成功率挑图；不自动等于统计上的随机无偏抽样。 |
| 探索性实验 | 用于发现规律、提出假设的有限实验；不应直接推广为所有数据的结论。 |
| positive / 正向组 | 实验预设支持主体→客体关系的候选词组；不保证每个改写在当前图片里严格同义。 |
| negative control / 负控制 | 预设角色反转、情境冲突或无关表达，用于对比分数；不等于每个短语都经人工证明为假。 |
| paraphrase / synonym / 同义改写 | 换一种说法表达相近关系；mounted on等词在具体语境中未必与riding完全等价。 |
| role reversal / 角色反转 | 交换关系中谁做动作、谁承受动作；骑着与被骑着，不能只看词面相近。 |
| margin / 间隔 | 两组分数之间的差；E01用最高正向logit减最高控制logit。负数意味着控制组有更高分。 |
| winner | 当前候选集合中分数最高的短语，不是人工认证的正确答案。 |
| expanded | 扩充后的词表条件，T01包含11个短语。 |
| original_control / synonym_only | 原词加控制词 / 用改写替掉原词的对照词表。 |
| 一致性 / consistency | 改写或替换后预设判断是否保持；需要看具体定义，不能直接当主表准确率。 |
| 语义 / semantic关系 | 本实验把带动作等关系划为此组；与空间组划分由研究者明确指定。 |
| 空间 / spatial关系 | 本实验选出的11个静态关系列表，不是按模型alpha自动分组，也不是官方所有空间真值。 |
| blur / radius12 | 模糊图像；本轮在448图上用半径12设置，保留框及GT。 |
| grayscale | 灰度图；用固定亮度权重将RGB合成，再复制成三通道。 |
| mean_image | 每张图每个颜色通道取空间均值，铺成均匀颜色图。不是数据集所有图片的平均图。 |
| permuted | 图像错配条件；将300图按固定位置轮换，保留原本那张图的框和GT。 |
| OOD / 分布外输入 | Out of Distribution：不符合正常图片/标注配套分布的输入，如错图配原框。 |
| 几何先验 / 语言先验 | 模型利用框布局规律 / 关系表达的常见模式做判断；可能帮助预测，也可能掩盖视觉错误。 |
| 因果贡献 / 因果解释 | 某因素的改变确实导致结果变化，需要控制其他影响；仅有高注意力不足以证明。 |
| 相关性 | 两个现象一起变化；不必然是一个导致另一个。 |
| 消融 / ablation | 去掉某模块或损失做比较；推理时关模块与删掉后重新训练是不同实验。 |
| 混杂因素 | 同时影响比较结果的其他因素，如模糊还会改变采样分数，不能把下降全归给某个模块。 |
| 显著性检验 / 置信区间 | 用统计方法估计差异是否可能由抽样波动造成 / 估计不确定范围；本报告没有把微小差值冒充显著提升。 |
| 人工复核 / assistant visual inspection | 人或助手对图像与标注的检查；本轮是助手探索性查看，不是第二人独立盲审。 |
| 未标注不等于负例 | GT没有某条关系，可能是漏标，而非关系肯定不存在；统计输出正确率时尤其要注意。 |

## L. 把原文中的几句话翻译成白话

**原文：“GT框、448、BF16、batch8、graph_constraint=True、pair_weight=1。”**

意思是：使用数据提供的框，每张图片缩成448×448；采用自动混合精度，一次算8张图；每个有向物体对只留下一个最高分关系；排序时把物体对相关性分数按1倍加进去。这些是固定实验设置，不是实验结果。

**原文：“候选覆盖很高，但谓词/排序退化。”**

意思是：模型大多已经挑中了需要判断的那两件东西；问题主要出在把关系叫错了，或者叫对了但把它排得太靠后。不是简单“没看见这两件东西”。

**原文：“FP32重构logit与实际BF16前向logit不同。”**

意思是：为了方便解释，把向量取出来用更高精度重新按公式算一次，数字与原来混合精度的整网运算有小差别。正式评分采用原前向结果；教学复算不替代实测。

**原文：“不能从推理峰值推断训练峰值。”**

意思是：只算答案时不用为之后求梯度保存那么多东西；训练还需要保存中间激活、梯度和优化器状态。推理只用不到1GiB的某段测量结果，不代表训练也只需这点显存。

**原文：“注意力集中不是视觉语义理解的充分证据。”**

意思是：热图确实能显示某个查询更多读取哪里，但“读那里”不保证“正确理解了那里”，也不证明“没有那里就不可能预测”。要结合错误、遮挡或其他控制实验判断。

**原文：“开放词表接口可工作，但尚未证明严格未见语义泛化。”**

意思是：系统确实能给新写的词组算分；要证明它能理解从未学过的关系，还必须核查训练数据、语义重叠，并在合适的新概念测试集上验证。两种证据的强度不同。
