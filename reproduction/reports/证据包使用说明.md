# 证据包使用说明（2026-10-16）

审查时另一个机器仅有Markdown，导致图片、预测、脚本无法查验。新证据包保留整个目录层级，用于解决这一交付问题。不要只复制报告文件，也不要将Windows绝对路径硬改成Mac绝对路径。

压缩包为工作区的 `reproduction/delivery/RelateAnything_evidence_20261016.zip`。它包括官方固定源码、公开标注JSON与pack数组，以及本轮脚本、配置、manifest、图像图表、报告、逐图预测、张量和运行日志。历史归档不重复打包；当前原报告的上一版仍在本机archive中保留。

解压到任意目录后，先用浏览器打开 `reproduction/reports/index.html`，报告及HTML都保持相对链接。输入文件“实验报告审查意见.md”保留审查者原文，其中链接相对于审查者当时的Mac源码目录，单独标记为历史输入，不冒充已修复链接；其余生成报告的本地文件引用逐项核验。

## 不需要GPU的核验

只需要Python 3标准库，无需安装torch或CUDA：

```text
python reproduction/scripts/verify_evidence.py
```

也可以不解压，使用本机脚本直接核验zip：

```text
python reproduction/scripts/verify_evidence.py reproduction/delivery/RelateAnything_evidence_20261016.zip
```

核验会检查产物清单中每个文件的字节数和SHA256、从逐图GT/预测重新计算32个条件R/mR/F1@20/50/100、检查所有生成报告的文件链接，以及本次运行命令的起止时间和退出码。哈希证明打包后内容一致，不独立证明标注正确或论文结论成立。

## 在原Windows GPU环境重新执行

```powershell
& .\reproduction\scripts\run_all.ps1
```

按准备、E01/V01、T01、B01/E02/E03/E04、R01审计、绘图报告、术语副本、核验顺序运行。每个阶段由run_stage.py记录实际命令、开始/结束时间、脚本与配置摘要及完整日志。失败即终止，不会自动换CPU、换模型或降低分辨率/预算。

只跑新增审计时：

```powershell
& .\reproduction\scripts\run_all.ps1 -Stages review_audit.py,render_report.py,make_glossary_copy.py,verify_artifacts.py
```

## 外部资源与可重复性的边界

压缩包不重复包含整套官方模型权重、全部原图和Python虚拟环境。资源的版本见environment.json；逐文件摘要见 `reproduction/manifests/external_resources.json`。GPU推理需恢复这些同哈希资源和锁定依赖，包内CPU评分/核验则不需要它们。

在其他机器重跑GPU时，还要调整pack元数据内的img_dir/ann_source，以及环境激活路径；这些历史绝对路径仅用于恢复外部资源，不影响包内报告阅读和标准库复算。不能把此证据包称为“空机器零依赖的一键GPU复现”。当前只在原Windows RTX 5070 Ti环境执行过GPU复跑，没有声称在Mac执行过CUDA推理。

## 重新打包

在所有实验、报告与核验完成后执行：

```text
python reproduction/scripts/package_evidence.py
```

此操作检查旧资源哈希、刷新脚本哈希、生成可携相对路径产物清单，再分别对原目录和zip做标准库核验。压缩包不将自身列入自身哈希清单；包本身的SHA256另存delivery/package_verification.json。后续修改任何已打包文件，都需要重新核验、重新打包。
