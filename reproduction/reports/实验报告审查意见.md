## 1. 结论与证据等级

**实验设计与报告覆盖已超过原指导中“两项对照实验”的基本要求，但当前不能认定为“所有非训练要求均已不打折扣完成”，也不能签署“没有任何 fallback”的验收结论。**

主要原因：

1. 当前工作区只有报告和官方代码，未发现报告引用的 reproduction 脚本、原始预测、配置、manifest、日志和图表。报告中 65 个不同的本地引用全部无法解析到实际文件。报告描述的运行位于 Windows `D:\relateAny`，当前目录是 macOS `/Users/wcs081/Desktop/relateAny`；很可能仅同步了 Markdown，但这需要实际产物确认。
2. E01 部分改写并非语境等价，现有统计支持预设短语敏感性探针，不能直接当成严格同义鲁棒性评测。
3. RA-4M 生成审计没有执行；PSG 最终标注审查是另一项工作，不能替代它。原指南把完整数据生成审计列为可选亮点，因此这不是所有基础复现工作的阻断项，但也不能标记为已完成。
4. 小规模训练按用户说明列为本轮豁免范围，仍应记录“未执行”，而非“通过”。完整重训、其他评测轴与真实检测器实验原本也不是完成基础方案的必选条件。

本审查区分四种判断：报告写明、源码支持、文本数字复算通过、原始产物验证通过。前三者不等价于第四者。未找到证据不等于证据从未存在，也不构成结果造假的判断。

## 3. 已实际完成的核查

### 3.1 文本数值一致性

从报告附录逐行提取数字，用 Python 标准库复算：

- E01 24 对平均正负 logit 间隔约为 2.925033，与主表 2.9250 一致。
- E01 正向组内部范围均值约为 5.314696，与主表 5.3147 一致。
- 六组平均间隔均与汇总表一致。
- `5287 + 7453 + 445 + 41 = 13226`，与去重关系总数一致。
- `13609 - 383 = 13226`，与原始关系数和重复数的差一致。
- 从 B01 展示的差值推得 R=0.401066、mR=0.307615，调和均值约为 0.348179，与 34.82% 一致。
- E02 附录三种子 R 的均值和样本标准差与汇总在展示舍入允许范围内相符。不能从已四舍五入的表格强求再次聚合的末位完全相同。
- 29 行配对改善/退化计数的分母分别为 299 或 2177，与报告所述有 GT 的计分样本数一致；仍需核实被排除样本的具体原因。

这些检查只能排查报告内部算术问题，不能证明推理真实执行，也不能验证实验样本的真实性。

### 3.2 与官方代码对应

- [docs/results.md](docs/results.md) 的 PSG 行为 R=0.401、mR=0.306、F1=0.347，与报告官方参照一致。
- [relsgg/eval/evaluator.py](relsgg/eval/evaluator.py) 的 F1 确实是 R 与 mR 的调和均值，不是普通分类中的 precision/recall F1。
- 官方 R 使用图内去重 GT；类别召回累计方式与报告说明相符。
- [relsgg/training/engine.py](relsgg/training/engine.py) 使用 `min(eval_budget, geo_budget)` 设置评测最终预算。因此请求 500、实际 400 是公开的协议上限，不是内存不足后的临时降级。
- [relsgg/model/sampler.py](relsgg/model/sampler.py) 在 `targets=None` 时不会启用训练用 GT 强制保留。是否实验确实这样调用，仍需检查诊断脚本。

### 3.3 本地可访问性

当前目录不存在 `reproduction/`、`runs/`、`figures/`、`output/`、`manifests/`、`reports/`。报告 65 个不同本地链接全部缺失，在桌面范围搜索也未找到关键脚本或 HTML 产物。

原始报告中的 `../figures/...` 链接看起来依赖其原来位于 `reproduction/reports/` 的层级。仅把 Markdown 复制到项目根目录会破坏链接。应恢复完整目录树，或生成根目录阅读版本并同步修改相对路径；不能只改成仍不可访问的 Windows 绝对路径。

## 4. 优先问题与修复验收标准

### P0：补齐证据包，才能验收实际执行及无静默降级

至少需要：

- 实际执行的 `reproduction/scripts/`，包括启动器、评测、词表实验、扰动、可视化、验证脚本。
- 每次运行的配置、样本 ID、随机种子、命令、开始/结束时间、退出码和完整日志。
- checkpoint、文本学生、tokenizer、词表矩阵、数据包的版本和哈希，以及实际加载的权重分支。
- B01 逐图/逐类指标及可重算预测；E01 逐候选结果；E02/E04 各条件记录；T01 张量；V01 重算与精度诊断。
- `figures/`、`reports/*.html` 及产物清单。

验收：逐项检查 manifest 中的文件存在和哈希，确认配置与运行绑定；从原始输出重新计算关键指标；在原实验机器上至少抽取固定样本复跑，确认新输出与记录在声明容差内一致。静态审查通过也不意味着已完成 GPU 复跑。

### P1：E01 不能把语义变化归因于同义改写不稳定

报告已主动承认 `mounted on` 对乘车/乘船、`resting on` 对站立、`ahead of` 对静态前后关系不完全等价。这是正确的边界声明，但不会消除实验混杂。

当前 58.33% 改写胜出率混合了“等义改写失败”和“改写改变含义”。建议保留旧实验作为探索性短语探针，另建独立核验的 E01b：

1. 不参考模型分数，先按图片与主客体确认候选语义；标记等义、近义但有额外含义、不等义、不确定。
2. 对每个物体对验证负控制是否在该场景下确实不成立。相反词、角色反转不自动构成严格负例。
3. 只在经过核验的等义子集上报告“同义鲁棒性”；其余分层报告，不删除失败结果掩盖原结论。
4. 新设计使用另行固定的样本；若只能重标旧样本，明确属于事后诊断。
5. 以图像为聚类单位估计不确定性，不能把同图多物体对或同一对多改写当成独立图片。

E01 的缓存 query 和 FP32 文本头是合理的控制变量设计，不自动构成 fallback。为了支持“等价执行”的主张，仍需在固定样本上检查它与同精度完整前向的对应；单图 T01 不能替代全 24 对的一致性核查。

### P1：样本排除与数据版本差异必须逐项追踪

B01 报告从 2186 张原始图到 2179 张 pack，再到 2177 张计分，并指出 13609 与文献 13623 相差 14 条关系。披露差异是优点，但不是完成归因。

验收需要提供：

- 7 张转换排除图像的 ID、触发条件、转换器版本。
- 2 张未计分图像的 ID、原始/转换/加载后三个阶段的关系数量与原因。
- 300 图实验中 299 张计分的对应 ID，确认各条件使用相同计分集合。
- max_objects、谓词映射、框与关系过滤规则，检查是否截断或遗漏。
- 官方 pack 与本地 pack 的差集（若可获得官方资源）；无法获得时，把“当前公开转换版本下近似复现”作为结论，不声称逐数据完全一致。

无需人为补齐 14 条标注，也不能将正常协议过滤自动判定为作弊式跳样。

### P1：RA-4M 生成审计仍是未执行项

D01 的 24 对 PSG 助手语境审查、重复关系统计是额外分析。它没有检查 RA-4M 的语义轮、grow、空间轮与几何过滤。

若此项继续受资源限制，直接在验收表标为“未执行，可选项”，保留当前 PSG 分析的真实名称。如果导师明确要求生成审计，可先获取 RA-4M 最终标注做最终质量抽查；想评估各轮增益，还需要各阶段原始输出。不能用另一个 VLM 的生成替代 Gemma 后声称原配方复现。

### P2：E02/E04 的覆盖率解释需要结合预算

报告设置最终预算与几何预算都是 400。对超过预算的图，几何筛选留下的候选会全部进入后续关系计算，视觉相关性主要重排；候选不足时同理不会因为视觉分数删除全部有效候选。

因此 E04 固定框时，不同图像条件的 GT 候选覆盖相同，在当前配置下主要是结构上可预期的现象。不能把它当作“视觉采样器在图像干预下很鲁棒”的独立证据。

可保留当前设置用于正式协议分析。若另外研究采样器，单开 final_budget=128 的诊断条件，并明确其与主表协议不同；该扩展不是基本验收必需项。

### P2：V01 是数值诊断，不能认证为 BF16 运行时精确 attention

报告已经提供 BF16/FP32 显式重算差异，且部分单 patch 差达到约 0.19。FP32 重算不能消除其与原 BF16 路径不同的事实。

验收应查看 hook 捕获位置、Q/K 投影、缩放、位置编码和掩码是否正确，对照同精度显式 attention 输出。报告提出的 SDPA/快速执行路径需要脚本设置或 profiler 证据；不能仅从“PyTorch MHA”推断具体内核。当前官方 SoftSpatialPool 调用并未显式设置 `need_weights=False`，实际路径还受 eval、autocast 和 fastpath 等条件影响。

若保留 FP32 图，应一直标作诊断重算。数值偏差透明披露不是静默 fallback，但“精确还原原执行权重”的更强主张不成立。

### P2：两处需要修正或补充的报告表述

- 附录 C 的 `in_front_of_4` 行写“此例负间隔”，但该行间隔为 **+1.0184**，原词排名为 1。应回查源记录并修正文字，不能直接把分数改成负数。术语版也包含同样问题。
- T01 主线的 `being ridden by` 在人→自行车方向 predicate logit 约 **1.72595**，在自行车→人方向约 **−2.30661**；`carrying a rider` 也呈类似异常。该例可以作为角色反转表达的失败探针。不能只展示 riding 的正确高分就概括“方向识别成功”。其原因究竟是文本表征、视觉投影还是语境差异，需要额外检验。

## 5. “没有 fallback”具体应如何验收

不能把“源码没有修改”当作无 fallback 证明。官方代码本身包含兼容性路径。

| 检查项 | 当前发现或风险 | 需要的证据 |
| --- | --- | --- |
| EMA 权重 | `build_model_from_ckpt()` 在 EMA 缺失时可退到普通 model 权重 | 实际 checkpoint 字段、选择的分支与权重哈希；请求 EMA 且缺失时显式失败 |
| 严格加载 | `load_state()` 默认可容忍缺失/多余 key 并打印提示 | 明确的 strict 设置、完整差异列表与允许名单；训练专用 W_obj 等合法例外可单独说明 |
| 骨干配置 | checkpoint 无内嵌配置时可走外部预训练资源路径 | 是否触发、所用配置/权重版本，以及最终是否全部被目标 checkpoint 覆盖 |
| 图像与样本 | 自定义启动/数据代码尚未提供 | 文件缺失和解码错误是否直接失败，有无空白图替代或 try/except continue |
| 设备与精度 | 报告声明 CUDA/BF16，诊断 FP32 | 实际设备和 autocast 记录；OOM 后是否改变 batch、尺寸、预算或换 CPU |
| 文本空间 | 是否使用配套学生、tokenizer、模板和矩阵 | 哈希、谓词顺序、维度与完整编码日志；无其他模型/随机向量替代 |
| 缓存 | E01 有意缓存 query | 缓存键绑定权重、图像、框、精度与配置；新条件未读取旧条件结果 |
| 报告生成 | 依赖外部产物 | 缺文件时失败而不是自动填默认指标、沿用旧结果或生成示意图冒充实测 |
| 启动器 | run_all.ps1 不在当前交付中 | 子进程非零退出码能使整个运行失败，不继续生成“成功报告” |

以上是需要排除的路径，不表示它们已在用户实验中发生。用户要求“无 fallback”应理解为无未声明的模型、数据、协议或运行降级；官方公开的预算上限、明确设计的 FP32 诊断和科学上合理的缓存不应一律禁止。

最终可认证的表述应限定范围，例如：“已审查本次运行配置与加载日志，未发现未经声明的权重、数据、设备、精度或协议替代；抽样复跑通过。”不能用有限审查承诺所有未来输入和执行路径都没有 fallback。

## 6. 内容是否丰富，以及下一步顺序

就报告覆盖而言，已经充分丰富：正式基准、两项原建议对照、存在性项干预、图像干预、注意力诊断、样本追踪和失败阶段分析。现在最有价值的增量是证据闭环和有效性，不是继续增加几十种扰动。

推荐顺序：

1. **先补齐原始证据包并修复全部链接。**保留原 Windows 目录结构即可，不必先在 Mac 上安装 GPU 环境。
2. **审查脚本和日志，再复算与抽样复跑。**排除真实 fallback，绑定代码/配置/输出来源。
3. **修正 E01 语义控制与上述文字问题。**收窄不能支持的主张，不删除不利结果。
4. **补齐样本排除清单、数据差异和统计不确定性。**E03 小幅差异可用图像级配对 bootstrap；不能凭点估计宣称显著提升。E02 三种子标准差不等于测试集抽样置信区间。
5. **如果希望增强外部说服力，再增加 A6 或 A2 中一个独立正式轴。**这是提高论证广度的建议，不是追溯增加原基本要求。PSG 上标成“空间”的 pooled recall 不等价于 SpatialSense 的真假空间判断。
6. **最后整理分享材料。**将长表放附录，主讲基线、一个贯穿样本、两张对照图和清晰失败案例；报告长度不等于演讲质量。

在证据包未到位前，本次审查结论为：**书面方案与实验覆盖较强，基础算术与源码对应部分通过；实际执行、可重复性和无静默降级尚待验收。**
